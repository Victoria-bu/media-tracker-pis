# План реалізації — Media Tracker v1 + адендум

Реалізація REST API за порядком лабораторної роботи №5.
Календарне вікно проєкту: 1-30 листопада 2026.
Етапи 1-9 виконує агент. Gate (контрольні точки) виконує людина:
Foundation, Collections integrity, SPEC-ADDENDUM-GATE, TEST-GATE,
RELEASE-GATE. Рішення кожного Gate записується в logs/.

> У REST API реалізуються лише вимоги з боку сервера (api-design.md,
> розділ 1). Клієнтські вимоги (F-005, F-006, F-011, F-021, F-022a, F-023,
> F-024, F-026, F-027) і UI-вимоги (NF-004, NF-005, NF-008) в API-тестах не
> перевіряються: API лише віддає й зберігає дані для них.

## Паралельна робота

1. **Етапи 3 і 4 (12-16 листопада).** Теги з Sessions і Collections
   залежать лише від каталогу, а не одне від одного. Кожен іде у
   власній git-гілці, злиття відбувається перед G2.
2. **Етапи 6 і 7 (22-23 листопада).** Поки агент рефакторить код,
   пишеться документ адендуму в spec/. Вони не торкаються одне одного.

## Критичний шлях

1 → 2 → G1 → (3 ∥ 4) → G2 → 5 → 6 → 8а → TG → 8б → 9 → RG.
Гілка 7 → SG закінчується 23-го разом з етапом 6, запасу немає. Єдиний
запас часу це резерв 30 листопада, він покриває приблизно один цикл
REVISE.

## Оцінка людського часу (окремо від агента)

| Gate | Що перевіряє людина | Чисті зусилля |
|---|---|---|
| G1 | 19 AC (етапи 1-2) + 6 BDD, тести і лог | ~2-2,5 год |
| G2 | 12 AC (етапи 3-4) + AC-009 + 4 BDD, результат злиття | ~2 год |
| SG | повнота й несуперечливість адендуму, AC, вплив на артефакти | ~1 год |
| TG | тести відповідають AC, падають з очікуваної причини | ~1 год |
| RG | верифікація, сценарії вручну, матриця, рішення | ~2 год |

Крім Gate, людина переглядає git diff після етапів 1, 2, 3, 4, 5, 6,
8б, 9 (по ~20-30 хв, разом ≈3-4 год).

**Разом:** близько 11-13 годин людської роботи без дефектів і 15-18
годин, якщо трапиться один-два цикли REVISE. Темп проєкту задає
перевірка людиною, а не швидкість генерації коду.
